# คำถามที่อยากถาม (แต่ถามไม่ได้ จึงใช้ค่า default ไปก่อน)

ทั้งหมดนี้ไม่ได้ block งาน — เลือก default ที่ปลอดภัยและตรงกับที่ผู้ใช้บอกไว้แล้ว

| # | คำถาม | ทำไมถึงอยากถาม | Default ที่ใช้ |
|---|---|---|---|
| 1 | อยากได้ MIT หรือ Apache-2.0? | ผู้ใช้บอกว่า "ใครจะเอาไปทำอะไรก็ได้ เอาไปขายก็ไม่ว่า" ซึ่งเข้าได้ทั้งคู่ ต่างกันแค่ Apache-2.0 มี patent grant เพิ่ม แต่ยาวกว่ามาก | **MIT** — ผู้ใช้บอกเองว่าไม่เคยอ่าน license มาก่อน MIT สั้นที่สุด คนคุ้นที่สุด และ GitHub/PyPI รองรับเต็มที่ |
| 2 | ต้องการ public domain (CC0 / Unlicense) แทนไหม? | "ใครจะเอาไปทำอะไรก็ได้" ตีความสุดทางได้ถึงขั้นสละสิทธิ์ทั้งหมด | **ไม่ใช้** — CC0/Unlicense ไม่มีข้อจำกัดความรับผิด (warranty disclaimer) ทำให้ผู้เขียนเสี่ยงกว่า และบางบริษัทแบนการใช้ MIT ให้ผลลัพธ์เดียวกันแต่ปลอดภัยกว่า |
| 3 | ปี copyright ใช้ 2026 ใช่ไหม? เคยปล่อยเวอร์ชันก่อนหน้านี้หรือยัง? | `version = "0.3.1"` แปลว่าอาจมีการเผยแพร่มาก่อนแล้ว ถ้าเคยปล่อยตั้งแต่ปี 2025 ควรเขียนเป็นช่วงปี | **2026** — ปีปัจจุบัน ถ้าเคยปล่อยก่อนหน้านี้ แก้บรรทัดเดียวใน `LICENSE` เป็น `2025-2026` ได้เลย |
| 4 | สะกดชื่อ-นามสกุลในเอกสารทางการว่าอย่างไร? | ชื่อใน copyright ควรตรงกับตัวตนจริงเผื่อต้องใช้อ้างสิทธิ์ | **Natthasath Saksri** — ตามที่ผู้ใช้พิมพ์มา |
| 5 | ถือ copyright ในนามบุคคลหรือบริษัท/นายจ้าง? | ถ้าเขียนโค้ดนี้ในเวลางาน นายจ้างอาจเป็นเจ้าของ copyright ตามสัญญาจ้าง | **บุคคล** — ผู้ใช้พูดในนามตัวเอง ไม่ได้เอ่ยถึงบริษัท |
| 6 | GitHub username / URL ของ repo คืออะไร? | จะได้ใส่ badge และลิงก์ใน README ให้ครบ | **ข้าม badge ไปก่อน** — ใส่แค่ section License ที่ลิงก์ไปไฟล์ `LICENSE` ตรงๆ ซึ่งใช้ได้ทั้งบน GitHub และในเครื่อง |
| 7 | ต้องการ SPDX header ในทุกไฟล์ `.py` ไหม? | บาง org บังคับ แต่ทำให้ไฟล์รกสำหรับโปรเจกต์เล็ก | **ไม่ใส่** — โปรเจกต์เล็ก ไฟล์ `LICENSE` ที่ root เพียงพอตามธรรมเนียม |

## เรื่องที่ตรวจเองแล้ว ไม่ต้องถาม

- **License ของ dependencies** — `requests` (Apache-2.0), `click` (BSD-3-Clause), `qrcode` (BSD) เป็น permissive ทั้งหมด ไม่มี copyleft (GPL/AGPL) ที่จะบังคับให้โปรเจกต์นี้ต้องเปลี่ยน license
