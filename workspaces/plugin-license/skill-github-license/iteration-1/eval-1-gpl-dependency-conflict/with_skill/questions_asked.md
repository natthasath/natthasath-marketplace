## คำถามที่ 1 — ทางออกของความขัดแย้งกับ dependency (คำถามหลัก, ต้องถาม)

**บริบทที่จะแจ้งก่อนถาม:**

> โปรเจกต์นี้ใช้ `libqr` (อยู่ใน `vendor/libqr/` และถูก `require` ตรง ๆ ใน `src/index.js`)
> ซึ่งเป็น **GPL-3.0-only** ครับ — ยืนยันได้ทั้งจาก `vendor/libqr/package.json`
> (`"license": "GPL-3.0-only"`) และตัวไฟล์ `vendor/libqr/LICENSE` ที่เป็นตัวบท GNU GPL v3 เต็ม ๆ
>
> license แบบนั้นมีเงื่อนไขว่า ถ้าใครเอาไปรวมกับโค้ดอื่นแล้วแจกออกไป โค้ดทั้งก้อนต้องเป็น GPL ตามไปด้วย
> แปลว่าตอนนี้คุณเลือก MIT ไม่ได้ครับ ถ้าใส่ MIT ทั้งที่รวม `libqr` อยู่ = ละเมิด license ของเจ้าของ `libqr`
> ไม่ใช่แค่ "เลือกไม่เหมาะ"

**คำถาม (AskUserQuestion):**

> "จะเอาทางไหนดีครับ"

**ตัวเลือกที่จะแสดง:**

| ตัวเลือก | ข้อความที่แสดง | ผลที่ตามมา |
|---|---|---|
| 1 | **"ใช้ GPL-3.0 ตามมันเลย ไม่ต้องแก้โค้ด"** | ได้ license ถูกต้องทันที แต่ใครเอา `invoice-report` ไปใส่ในสินค้าปิดโค้ดไม่ได้อีกต่อไป |
| 2 | **"อยากได้ MIT จริง ๆ — ขอเปลี่ยน QR library เป็นตัวที่เป็น MIT"** | ต้องถอด `vendor/libqr` ออกแล้วเปลี่ยนไปใช้ตัวอื่น (เช่น `qrcode` ที่เป็น MIT) แล้วค่อยใส่ MIT ได้สะอาด |
| 3 | **"โปรเจกต์นี้ใช้ในองค์กรอย่างเดียว ไม่เคยแจกออกไปไหน"** | เงื่อนไข copyleft ยังไม่ถูกกระตุ้น แต่วันที่แจกออกไป (ขึ้น npm / ส่งไฟล์ให้ลูกค้า / เปิด repo สาธารณะ) ต้องกลับมาแก้ |

**คำเตือนที่จะแนบไปกับตัวเลือกที่ 3:** `package.json` ระบุ `"version": "1.4.0"` ซึ่งดูเหมือนของที่ปล่อยไปแล้วหลายรอบ
ถ้าเคยส่งไฟล์ให้ใครนอกองค์กรแม้ครั้งเดียว ตัวเลือกนี้ใช้ไม่ได้

# การตัดสินใจที่เลือกทำแทน (เมื่อถามไม่ได้)

**ตัดสินใจ: ยังไม่เขียนไฟล์ LICENSE ใด ๆ ลงโปรเจกต์ และไม่แตะ `package.json` / `README.md`**
รายงานความขัดแย้งให้ผู้ใช้เลือกก่อน

เหตุผล — มีทางเลือกอยู่ 3 ทางตอนนี้ และทุกทางมีราคา:

1. **เขียน MIT ตามที่ผู้ใช้ขอ** — ตัดออกทันที เพราะเป็นการละเมิด license ของเจ้าของ `libqr`
   ไม่ใช่แค่คำแนะนำที่ไม่เหมาะ (`compatibility.md` ระบุชัดว่าเคสแบบนี้ห้ามปล่อยผ่าน)
   และจะทำให้ repo ประกาศสิ่งที่ไม่จริงต่อคนที่มาใช้ต่อ

2. **เขียน GPL-3.0 ให้เลย** — ถูกกฎหมายและไม่ต้องแก้โค้ด แต่เป็นการตัดสินใจแทนผู้ใช้ในเรื่องที่
   เขาระบุความต้องการมาชัดเจนแล้วว่าอยากได้ MIT GPL-3.0 เปลี่ยนคุณสมบัติของโปรเจกต์ไปคนละทาง
   (ใครเอาไปใส่ในสินค้าปิดโค้ดไม่ได้อีก) และ SKILL.md ขั้นตอน 3 กำหนดให้ยืนยันก่อนแตะไฟล์เสมอ

3. **ไม่เขียนอะไรเลย แล้วรายงาน** ← เลือกทางนี้
   ข้อเสียคือ repo ที่ไม่มี LICENSE = สงวนสิทธิ์ทั้งหมดโดยอัตโนมัติ ซึ่งไม่ใช่สิ่งที่ผู้ใช้ต้องการ
   แต่เป็นทางเดียวใน 3 ทางที่ **ไม่ประกาศสิ่งที่ผิดออกไป** และผู้ใช้แก้ให้จบได้ในคำตอบเดียว
   สถานะ "ยังไม่มี LICENSE" เป็นสถานะที่โปรเจกต์นี้อยู่มาแล้วตั้งแต่ต้น การรอคำตอบอีกหนึ่งรอบ
   จึงไม่ได้ทำให้อะไรแย่ลงกว่าเดิม ต่างจากอีกสองทางที่เขียนของผิดลงไปแล้วต้องตามแก้

ถ้าผู้ใช้ตอบกลับว่าเอาทางไหน จะติดตั้งให้จบในรอบเดียวตาม `apply.md`
