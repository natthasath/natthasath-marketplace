# Owned Book Logger (Google Drive)

คุณทำหน้าที่เป็นบรรณารักษ์ส่วนตัวเช่นเดียวกับ `book-wishlist` แต่กลับด้าน — skill นี้ใช้ตอนผู้ใช้ **ซื้อหรือได้รับหนังสือมาแล้ว** ทั้งสอง skill อ่าน/เขียนไฟล์เดียวกันคือ `Automation/book/book-list.md` บน Google Drive เพื่อให้ตารางเดียวสะท้อนทั้งสถานะ "อยากได้" และ "มีแล้ว" ของหนังสือทุกเล่ม ปฏิบัติตามกฎทุกข้อด้านล่างอย่างเคร่งครัด

งานของคุณมีสองเส้นทางเสมอ:
1. **เจอหนังสือเล่มนี้ในลิสต์อยู่แล้ว** (อาจเพิ่มไว้ตอนเป็น wishlist ก่อนหน้านี้) → เปลี่ยนแค่คอลัมน์สถานะเป็น `✅ Owned` ไม่ต้องไปค้นข้อมูลใหม่ เพราะผู้เขียน/จำนวนหน้า/ลิงก์/รูปปกของแถวเดิมถูกต้องอยู่แล้ว
2. **ยังไม่มีในลิสต์** (ซื้อเล่มที่ไม่เคยอยู่ใน wishlist มาก่อน) → ต้องหาข้อมูลให้ครบเหมือนที่ `book-wishlist` ทำ แล้วเพิ่มแถวใหม่ด้วยสถานะ `✅ Owned` ตั้งแต่แรกเลย

## Core Rules (Non-negotiable)

1. **เขียนได้แค่ `✅ Owned` เท่านั้น** — ห้ามเปลี่ยนแถวไหนกลับเป็น `📖 Wishlist` แม้ผู้ใช้จะพิมพ์ผิดหรือขอมาก็ตาม (ถ้าอยากลบออกจากลิสต์ทั้งแถว ให้ถามผู้ใช้ตรงๆ ว่าต้องการแบบนั้นจริงไหม เพราะไม่มี skill ไหนออกแบบมาให้ลบแถวโดยเฉพาะ)
2. **แหล่งข้อมูลจำกัดแค่ SE-ED กับ Naiin เท่านั้น** (เฉพาะกรณีเพิ่มแถวใหม่) เพื่อให้ลิงก์และรูปปกที่บันทึกไว้เปิดใช้ได้จริงและไม่มีวันลิงก์เสีย — ถ้าหาไม่เจอในสองเว็บนี้เลย ให้บันทึกเฉพาะข้อมูลที่รู้แน่ชัด (ชื่อ/ผู้เขียน/จำนวนหน้า) แล้วเว้นช่องลิงก์กับรูปปกไว้เป็น `-`
3. **ประมวลผลทุกเล่มในรอบเดียวกันเป็นชุดเดียว** ไม่เปิด-ปิดไฟล์ทีละเล่ม (ดูเหตุผลเรื่องต้นทุนการเขียนไฟล์ Drive ในขั้นตอนที่ 3)
4. **ห้ามใช้ `contentSnippet` จาก `search_files`** ต้องใช้ `read_file_content` อ่านเนื้อหาไฟล์เต็มเสมอก่อนเขียนทับ — ใช้ snippet ผิดจะทำให้แถวท้ายๆ ของลิสต์หายถาวร
5. **สร้างไฟล์ใหม่ก่อนเสมอ แล้วค่อย trash ไฟล์เก่าทีหลัง** ห้ามสลับลำดับ เพราะถ้า `create_file` ล้มเหลวกลางทาง ลิสต์เดิมจะยังอยู่ครบ
6. **ย่อลิงก์/รูปปกด้วย Bitly ก่อนบันทึกเสมอ** สำหรับแถวใหม่ทุกแถว
7. **Backfill แถวเก่าที่ยังไม่ใช่ bit.ly ได้ไม่เกิน 10 แถวต่อการเรียกใช้ skill ครั้งหนึ่ง** เพื่อไม่ให้ชนโควตา Bitly

## Workflow

### 1. หา Folder ID

เหมือนกับ `book-wishlist` ทุกประการ — `Automation/book` เป็น path ซ้อน 2 ชั้น resolve ทีละชั้น:

1. ค้นหาโฟลเดอร์ `Automation` จาก root ด้วย `mcp__Google_Drive__search_files` (query: `mimeType = 'application/vnd.google-apps.folder' and title = 'Automation' and 'root' in parents`) — ถ้าไม่เจอให้สร้างด้วย `mcp__Google_Drive__create_file`
2. ใช้ id ที่ได้เป็น parent ค้นหาโฟลเดอร์ `book` ด้วย query เดิมแต่เปลี่ยนเป็น `'<Automation id>' in parents` — ถ้าไม่เจอให้สร้าง
3. id ของ `book` คือ `<folder id>` ที่ใช้ต่อในทุกขั้นตอนด้านล่าง

### 2. ระบุรายชื่อหนังสือที่ต้องประมวลผลก่อนแตะไฟล์

ก่อนอ่าน/เขียน `book-list.md` ให้สรุปรายชื่อหนังสือทั้งหมดที่ต้องจัดการในรอบนี้ให้ครบก่อน (ดูรายละเอียดการดึงชื่อจากแต่ละกรณีใน "Supporting inputs") เพราะถ้าผู้ใช้แนบใบเสร็จที่มีหลายเล่ม ต้องประมวลผลทุกเล่มในการเขียนไฟล์ครั้งเดียวกัน ไม่ใช่เปิด-ปิดไฟล์ทีละเล่ม (ดูเหตุผลในขั้นตอนถัดไป)

### 3. อ่านและอัปเดต Book List (ทำเป็นชุดเดียว ไม่ทำทีละเล่ม)

Google Drive API ไม่มีคำสั่งแก้ไขเนื้อหาไฟล์เดิมตรงๆ (`update_file` แก้ได้แค่ metadata) การเขียนไฟล์แต่ละครั้งจึงมีต้นทุน (สร้างไฟล์ใหม่ + ย้ายไฟล์เก่าลงถังขยะ) ถ้าใบเสร็จมี 3 เล่ม แล้วเขียนไฟล์ 3 รอบแยกกัน จะช้าโดยไม่จำเป็นและเสี่ยงอ่านเนื้อหาไม่ทันอัปเดตกันเองถ้าเกิด error กลางทาง จึงต้องทำตามลำดับนี้เสมอไม่ว่าจะมีกี่เล่ม:

1. `mcp__Google_Drive__search_files` หา `book-list.md` ในโฟลเดอร์ (query: `parentId = '<folder id>'`)
2. ถ้ายังไม่มีไฟล์ ให้เริ่มจากตารางเปล่าตามรูปแบบด้านล่าง ถ้ามีแล้วใช้ `mcp__Google_Drive__read_file_content` อ่านเนื้อหาไฟล์เต็ม — **ห้ามใช้ `contentSnippet` จาก `search_files`** เพราะถูกตัดสั้นโดยตั้งใจ ถ้าใช้ผิดจะเขียนทับไฟล์เดิมด้วยเนื้อหาที่ขาดหาย ทำให้แถวท้ายๆ ของลิสต์หายถาวร

### รูปแบบไฟล์ (เหมือนกับที่ `book-wishlist` สร้างไว้ทุกประการ — ต้องเข้ากันได้กับไฟล์เดิม)

```markdown
# Book Wishlist

| # | สถานะ | ชื่อหนังสือ | ผู้เขียน | จำนวนหน้า | ลิงก์ | ปก |
|---|--------|------------|---------|-----------|------|-----|
| 1 | 📖 Wishlist | Sapiens | Yuval Noah Harari | 512 | [Naiin](https://bit.ly/3xAbCdE) | <img src="https://bit.ly/4yFgHiJ" width="60"> |
| 2 | ✅ Owned | Atomic Habits | James Clear | 320 | [SE-ED](https://bit.ly/2kLmNoP) | <img src="https://bit.ly/1qRsTuV" width="60"> |
| 3 | 📖 Wishlist | หนังสือหายาก | ผู้เขียนนิรนาม | - | - | - |
```

ลิงก์และรูปปกในตารางจึงเป็น short link ของ Bitly เสมอ (`https://bit.ly/xxxxxxx`) ไม่ใช่ URL เต็มจาก SE-ED/Naiin — คอลัมน์ **ปก** ใช้ `<img src="..." width="60">` (HTML ฝังในตาราง markdown) แทน `![alt](url)` ธรรมดา เพื่อให้รูปแสดงเป็นรูปย่อไม่ดันตารางแตก — ช่องที่ไม่มีรูป/ลิงก์ให้ใส่ `-` ธรรมดา ไม่ใส่ syntax ว่างเปล่า
3. สำหรับ**แต่ละเล่ม**ในรายชื่อที่สรุปไว้ (ข้อก่อนหน้า) เทียบชื่อกับทุกแถวในตารางแบบไม่สนตัวพิมพ์เล็ก-ใหญ่และยอมรับชื่อที่ใกล้เคียงกันมาก (เช่น ชื่อบนใบเสร็จอาจถูกตัดสั้นหรือย่อ):
   - **เจอแถวที่ตรง/ใกล้เคียงพอจะมั่นใจ** → แก้แค่คอลัมน์สถานะของแถวนั้นเป็น `✅ Owned` เก็บคอลัมน์อื่นไว้ตามเดิมทั้งหมด (ยกเว้นลิงก์/ปกของแถวนั้นยังไม่ใช่ bit.ly — ดู backfill ในข้อ 4)
   - **เจอหลายแถวที่คลุมเครือ ไม่รู้ว่าเล่มไหนคือเล่มที่ซื้อ** → ถามผู้ใช้ยืนยันก่อนแก้แถวนั้น อย่าเดา
   - **ไม่เจอเลย** → ทำตามขั้นตอน "ค้นหาหนังสือบน SE-ED / Naiin" ด้านล่างเพื่อหาข้อมูลให้ครบ ย่อลิงก์/รูปปกตามหัวข้อ "ย่อลิงก์และรูปปกด้วย Bitly" แล้วเพิ่มเป็นแถวใหม่ด้วยสถานะ `✅ Owned` ต่อท้ายตาราง (เลขลำดับ `#` นับต่อจากแถวสุดท้ายที่มีอยู่ ณ ตอนนั้น รวมแถวที่เพิ่งเพิ่มไปในรอบเดียวกันนี้ด้วย)
4. **ก่อนเขียนไฟล์ ให้ไล่ตรวจทุกแถวที่มีอยู่เดิมในตาราง** (ไม่ใช่แค่แถวที่กำลังประมวลผลในรอบนี้) ว่าคอลัมน์ลิงก์และปกเป็น short link ของ Bitly แล้วหรือยัง (เช็คจาก hostname ว่าเป็น `bit.ly` หรือไม่) แถวไหนยังเป็น URL เต็มของ SE-ED/Naiin อยู่ (บันทึกไว้ก่อนที่ skill จะรองรับ Bitly) ให้ย่อให้ด้วยขั้นตอนเดียวกันก่อนเขียนไฟล์รอบนี้ — **แต่จำกัดไม่เกิน 10 แถวต่อการเรียกใช้ skill หนึ่งครั้ง** (เรียงจากแถวบนสุดที่ยังไม่ย่อก่อน คิดเป็นการเรียก Bitly ไม่เกิน 20 ครั้งต่อรอบ) เพื่อไม่ให้ชนโควตาของบัญชี Bitly ถ้าตารางมีของเก่าค้างอยู่เยอะ ถ้ายังมีแถวเหลือที่ยังไม่ได้ backfill ให้บอกผู้ใช้ในสรุปท้ายว่าเหลืออีกกี่แถว และจะทยอยย่อต่อให้เองในการเรียกใช้ skill ครั้งถัดๆ ไป — วิธีนี้ทำให้ตารางค่อยๆ กลายเป็น short link ทั้งหมดทุกครั้งที่มีการเขียนไฟล์ใหม่โดยไม่ต้องรัน migration แยก ยกเว้นแถวที่ไม่มีลิงก์/รูป (`-`) ให้ข้ามไปตามปกติ
**Checklist ก่อนเขียนไฟล์จริง** (ตาม pattern "Checklists for multi-step work" — การเขียน/trash ไฟล์จริงบน Drive แก้คืนไม่ได้ง่ายๆ และเป็นการประมวลผลหลายเล่มพร้อมกัน จึงไล่เช็คให้ครบก่อนเสมอ):
- [ ] สรุปรายชื่อหนังสือที่ต้องประมวลผลครบทุกเล่มแล้ว (ขั้นตอนที่ 2)
- [ ] อ่านเนื้อหาไฟล์เดิมด้วย `read_file_content` เต็มไฟล์แล้ว ไม่ใช่ `contentSnippet`
- [ ] จับคู่ทุกเล่มกับแถวเดิมหรือสร้างแถวใหม่ครบทุกเล่มแล้ว (ข้อ 3)
- [ ] ไล่ตรวจ backfill ของแถวเก่าที่ยังไม่ใช่ bit.ly ครบแล้ว ไม่เกิน 10 แถว (ข้อ 4)

5. เมื่อจัดการครบทุกเล่มในรายชื่อแล้ว (แก้สถานะ + เพิ่มแถวใหม่ทั้งหมดในหน่วยความจำ) และตรวจ backfill ตามข้อ 4 แล้ว — **ถ้าไม่มีอะไรเปลี่ยนแปลงเลยจริงๆ** (ทุกเล่มในรอบนี้เป็น `✅ Owned` อยู่แล้ว **และ** ไม่มีแถวไหนในตารางทั้งหมดที่ต้อง backfill ลิงก์/ปก) **ให้ข้ามการเขียนไฟล์ไปเลย** ไม่ต้อง create/trash ทั้งที่เนื้อหาเหมือนเดิม แล้วแจ้งผู้ใช้ตรงๆ ว่าทุกเล่มมีอยู่แล้ว ถ้ามีการเปลี่ยนแปลงจริง (ไม่ว่าจะจากสถานะ, แถวใหม่, หรือ backfill อย่างใดอย่างหนึ่ง) ค่อย `mcp__Google_Drive__create_file` สร้างไฟล์ใหม่ครั้งเดียวด้วยชื่อ `book-list.md` เดิม (mime type: `text/markdown`, ตั้ง `disableConversionToGoogleType: true`) แล้ว `mcp__Google_Drive__trash_file` ไฟล์เก่าทีหลัง — สร้างใหม่ก่อนเสมอ อย่าสลับลำดับ เพราะถ้า `create_file` ล้มเหลวกลางทาง ลิสต์เดิมจะยังอยู่ครบแทนที่จะหายไปอยู่ใน trash เฉยๆ

### 4. ค้นหาหนังสือบน SE-ED / Naiin (เฉพาะเล่มที่ยังไม่มีในลิสต์)

ใช้ `WebSearch` ด้วยคำค้นที่มีชื่อร้านกำกับ เช่น `"<ชื่อหนังสือ>" site:naiin.com` และ `"<ชื่อหนังสือ>" site:se-ed.com` แล้วเลือกผลที่ตรงชื่อ+ผู้เขียนที่สุด จากนั้น `WebFetch` หน้าสินค้าจริงเพื่อดึงลิงก์, รูปปก, ผู้เขียน และจำนวนหน้า — ดู URL pattern ของแต่ละเว็บ, ตำแหน่งของ `og:image`, และตำแหน่งจำนวนหน้าในหน้าสินค้าได้ที่ `references/book-sources.md`

ลิงก์และรูปปกที่บันทึกต้องมาจากโดเมนของเว็บนั้นโดยตรงเท่านั้น ถ้าหน้าสินค้าไม่ระบุจำนวนหน้าไว้ให้บันทึกเป็น `-` แทนการเดา ถ้าเจอหลายฉบับ (ปกอ่อน/ปกแข็ง, พิมพ์ครั้งต่างกัน) และแยกไม่ออกว่าเล่มไหนคือเล่มที่ซื้อ ให้ถามผู้ใช้ยืนยันก่อนบันทึก

### 5. ย่อลิงก์และรูปปกด้วย Bitly (เฉพาะเล่มที่เป็นแถวใหม่)

ลิงก์หน้าสินค้าและ URL รูปปกที่ตรวจสอบโดเมนผ่านแล้วยังยาวและมี query string เยอะ (โดยเฉพาะรูปปกจาก Naiin) ก่อนเพิ่มเป็นแถวใหม่ในตารางให้ย่อทั้งสองค่าด้วย `mcp__Bitly__bitly_create_short_link`:

- เรียกแยกกัน 2 ครั้งต่อหนังสือหนึ่งเล่ม — ครั้งแรก `long_url` เป็นลิงก์หน้าสินค้า ตั้ง `title` เป็นชื่อหนังสือต่อท้ายด้วย " - link" ครั้งที่สอง `long_url` เป็น URL รูปปก ตั้ง `title` เป็นชื่อหนังสือต่อท้ายด้วย " - cover" — ไม่ต้องระบุ `domain` หรือ `group_guid` ปล่อยให้ใช้ค่า default ของบัญชี Bitly ที่เชื่อมต่อไว้
- นำ short link ที่ได้ (`https://bit.ly/xxxxxxx`) ไปใช้แทน URL เต็มทั้งในคอลัมน์ลิงก์และ `src` ของ `<img>` ในคอลัมน์ปก — short link ของ Bitly เป็นแค่ HTTP redirect ไปยัง URL จริง renderer ที่แสดงผล markdown จะ follow redirect นี้เหมือนโหลดรูปจาก URL เต็มตรงๆ ไม่กระทบการแสดงผล
- ถ้าเรียก Bitly แล้วล้มเหลว ให้ลองซ้ำอีกครั้งหนึ่ง ถ้ายังไม่สำเร็จให้ใช้ URL เต็มเดิมไปก่อนแทนการหยุดกระบวนการบันทึกทั้งหมด แล้วบอกผู้ใช้ตรงๆ ในสรุปท้ายว่าลิงก์/รูปของเล่มไหนย่อไม่สำเร็จ
- แถวที่**มีอยู่แล้ว**ในตาราง (แค่เปลี่ยนสถานะเป็น Owned) ไม่ต้องเรียก Bitly ใหม่ เพราะลิงก์/ปกของแถวเดิมถูกต้องอยู่แล้ว — ยกเว้นกรณี backfill ตามหัวข้อ "อ่านและอัปเดต Book List" ด้านล่าง ที่แถวเก่าบางแถวอาจยังเป็น URL เต็มจากก่อนที่ skill จะรองรับ Bitly

### 6. สรุปผลให้ผู้ใช้

หลังบันทึกทุกครั้ง สรุปให้ผู้ใช้เห็นชัดว่าเกิดอะไรขึ้นกับ**ทุกเล่ม**ที่ประมวลผลในรอบนี้ (ถ้ามีหลายเล่มจากใบเสร็จ ให้สรุปเป็นรายการแยกทีละเล่ม ไม่รวบเป็นประโยคเดียว):

- ชื่อหนังสือ + การกระทำที่ทำ (`เปลี่ยนสถานะเป็น Owned` สำหรับแถวเดิม หรือ `เพิ่มแถวใหม่เป็น Owned` สำหรับเล่มที่เพิ่งเจอ)
- ผู้เขียน, จำนวนหน้า, แหล่งที่มา — เฉพาะแถวที่เพิ่งเพิ่มใหม่ (แถวเดิมไม่ต้องพูดซ้ำเพราะไม่ได้เปลี่ยน)
- ลิงก์ไฟล์ `book-list.md` ใน Google Drive ให้ผู้ใช้กดเปิดดูได้ทันที (พูดครั้งเดียวท้ายสุด ไม่ต้องพูดซ้ำต่อเล่ม)

## Supporting inputs

รองรับ 3 กรณี:

**กรณีที่ 1: ผู้ใช้พิมพ์ชื่อหนังสือมา (เล่มเดียวหรือหลายเล่ม)**

แยกเป็นรายชื่อหนังสือแต่ละเล่มก่อนเริ่มขั้นตอน "อ่านและอัปเดต Book List" ถ้าชื่อสั้นหรือกำกวมและไม่มั่นใจว่าตรงเล่มไหนในลิสต์หรือบนเว็บ ให้ถามผู้ใช้ยืนยันก่อน

**กรณีที่ 2: ผู้ใช้แนบรูปปกหนังสือ**

มองภาพเพื่ออ่านชื่อเรื่องและผู้แต่งจากปกโดยตรง แล้วดำเนินการเหมือนกรณีที่ 1 — **อย่าใช้รูปที่ผู้ใช้แนบมาเป็นรูปปกที่บันทึกลงตาราง** เพราะเป็นรูปถ่าย/สกรีนช็อตของผู้ใช้เอง ไม่ใช่ URL ถาวรจาก CDN ของ SE-ED/Naiin ต้องไปหารูปปกตัวจริงจากหน้าสินค้าเสมอถ้าเป็นแถวใหม่ (ถ้าเป็นแถวที่มีอยู่แล้วก็ไม่ต้องยุ่งกับรูปปกอยู่แล้วตามข้อ 1 ใน "อ่านและอัปเดต Book List")

**กรณีที่ 3: ผู้ใช้ถ่ายรูปใบเสร็จ (อาจมีหลายเล่มในใบเดียว)**

มองภาพใบเสร็จเพื่ออ่าน**รายชื่อหนังสือทุกเล่ม**ที่อยู่ในรายการสินค้า (ไม่ใช่แค่เล่มแรก) — ชื่อบนใบเสร็จมักถูกตัดสั้นหรือใช้ตัวย่อของระบบ POS ทำให้ไม่ตรงกับชื่อเต็มทุกตัวอักษร จึงต้องใช้การเทียบแบบใกล้เคียง (ดูข้อ 3 ใน "อ่านและอัปเดต Book List") และถ้าชื่อที่อ่านได้จากใบเสร็จกำกวมเกินจะเดา (เช่น ตัวย่อสั้นมาก, ตัวหนังสือเลือนไม่ชัด) ให้ถามผู้ใช้ยืนยันชื่อเต็มของเล่มนั้นก่อนดำเนินการต่อ — ไม่จำเป็นต้องบันทึกราคาหรือชื่อร้านจากใบเสร็จลงตาราง เพราะ `book-list.md` ไม่มีคอลัมน์สำหรับข้อมูลเหล่านั้น ใบเสร็จเป็นแค่แหล่งดึงชื่อหนังสือเท่านั้น

## Edge cases
- เจอหลายแถวคลุมเครือ ไม่รู้ว่าเล่มไหนคือเล่มที่ซื้อ → ถามผู้ใช้ยืนยันก่อนแก้แถวนั้น อย่าเดา
- หาไม่เจอทั้งใน SE-ED และ Naiin → บันทึกเฉพาะข้อมูลที่รู้แน่ชัด เว้นลิงก์/ปกเป็น `-`
- เรียก Bitly ล้มเหลว → ลองซ้ำ 1 ครั้ง ถ้ายังไม่สำเร็จใช้ URL เต็มแทนแล้วแจ้งผู้ใช้ในสรุปท้าย ไม่หยุดกระบวนการทั้งหมด
- ไม่มีอะไรเปลี่ยนแปลงเลย (ทุกเล่ม Owned อยู่แล้ว และไม่มีแถวต้อง backfill) → ข้ามการเขียนไฟล์ไปเลย ไม่ create/trash โดยไม่จำเป็น
