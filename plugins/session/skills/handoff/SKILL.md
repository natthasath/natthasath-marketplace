# บทบาท:
คุณทำหน้าที่เขียนเอกสารส่งไม้ต่อ (handoff document) สรุปสิ่งที่เกิดขึ้นใน session นี้ ให้ agent ใหม่ที่
ไม่มี context ใดๆ เลยอ่านแล้วทำงานต่อได้ทันที โดยไม่ต้องไล่อ่าน transcript เดิมทั้งหมด — ต่างจาก
`session:session-name` ที่ตั้งชื่อ/บันทึกจุดประสงค์ตอน**เริ่ม** session, `handoff` ทำหน้าที่ปิดท้ายตอน
**จบ** session แทน

# ขั้นตอน:

## 1. สรุปบทสนทนาปัจจุบัน
เขียนสรุปว่า session นี้ทำอะไรไปแล้ว ตัดสินใจอะไรไปบ้าง และเหลืออะไรที่ยังไม่เสร็จ

## 2. อ้างอิงแทนการก็อปซ้ำ
ถ้าเนื้อหาถูกบันทึกไว้แล้วใน artifact อื่น (spec, plan, ADR, issue, commit, diff) **ห้ามก็อปมาแปะซ้ำ**
ให้อ้างอิง path หรือ URL แทน — ป้องกันเอกสาร handoff บวมและข้อมูลสองชุดไม่ตรงกันภายหลัง

## 3. เสนอ skill ที่ควรใช้ต่อ
ใส่ section "Suggested skills" แนะนำ skill ที่ session ถัดไปน่าจะต้องเรียกใช้ตาม context ที่เหลืออยู่

## 4. Redact ข้อมูลอ่อนไหว
ก่อนบันทึก ให้ตรวจและลบ/blank ข้อมูลอ่อนไหวออกทั้งหมด เช่น API key, password, หรือข้อมูลส่วนตัวที่
ระบุตัวตนได้ (PII) — ไม่มีข้อยกเว้น แม้ผู้ใช้จะไม่ได้ขอให้ redact ก็ตาม

## 5. ปรับตาม argument ถ้ามี
ถ้าผู้ใช้ระบุ argument มาตอนเรียก (`/handoff <คำอธิบาย>`) ให้ตีความเป็นคำอธิบายว่า session ถัดไปจะ
โฟกัสเรื่องอะไร แล้วปรับเนื้อหาเอกสารให้ตรงกับโฟกัสนั้น

## 6. บันทึกไฟล์
เซฟไปที่ temp directory ของ OS ผู้ใช้ (`%TEMP%` บน Windows, `$TMPDIR` หรือ `/tmp` บน macOS/Linux) —
ไม่ใช่โฟลเดอร์โปรเจกต์ปัจจุบัน เพราะเอกสาร handoff เป็นของชั่วคราวเฉพาะรอบส่งต่อ ไม่ใช่ artifact ถาวร
ของโปรเจกต์ แล้วบอก path ที่บันทึกไว้กับผู้ใช้

# คำขอ:
- ห้ามก็อปเนื้อหาที่มีอยู่แล้วใน artifact อื่นมาแปะซ้ำในเอกสาร handoff เด็ดขาด ให้อ้างอิงแทนเสมอ
- ต้อง redact secret/PII ทุกครั้งก่อนบันทึก ไม่มีข้อยกเว้น
- บันทึกไฟล์ที่ temp directory ของ OS เท่านั้น ไม่ใช่ในโปรเจกต์ปัจจุบัน
