# Session Handoff Writer

คุณทำหน้าที่เขียนเอกสารส่งไม้ต่อ (handoff document) สรุปสิ่งที่เกิดขึ้นใน session นี้ ให้ agent ใหม่ที่
ไม่มี context ใดๆ เลยอ่านแล้วทำงานต่อได้ทันที โดยไม่ต้องไล่อ่าน transcript เดิมทั้งหมด — ต่างจาก
`session:session-name` ที่ตั้งชื่อ/บันทึกจุดประสงค์ตอน**เริ่ม** session, `handoff` ทำหน้าที่ปิดท้ายตอน
**จบ** session แทน

## Core Rules (Non-negotiable)

1. **ห้ามก็อปเนื้อหาที่มีอยู่แล้วใน artifact อื่นมาแปะซ้ำในเอกสาร handoff เด็ดขาด** ให้อ้างอิง path หรือ URL แทนเสมอ — ป้องกันเอกสารบวมและข้อมูลสองชุดไม่ตรงกันภายหลัง
2. **ต้อง redact secret/PII ทุกครั้งก่อนบันทึก ไม่มีข้อยกเว้น** แม้ผู้ใช้จะไม่ได้ขอให้ redact ก็ตาม
3. **บันทึกไฟล์ที่ temp directory ของ OS เท่านั้น** ไม่ใช่ในโปรเจกต์ปัจจุบัน เพราะเอกสาร handoff เป็นของชั่วคราวเฉพาะรอบส่งต่อ

## Workflow

### 1. สรุปบทสนทนาปัจจุบัน
เขียนสรุปว่า session นี้ทำอะไรไปแล้ว ตัดสินใจอะไรไปบ้าง และเหลืออะไรที่ยังไม่เสร็จ

### 2. อ้างอิงแทนการก็อปซ้ำ
ถ้าเนื้อหาถูกบันทึกไว้แล้วใน artifact อื่น (spec, plan, ADR, issue, commit, diff) ให้อ้างอิง path หรือ URL แทนตามหลักข้อ 1 ของ Core Rules

### 3. เสนอ skill ที่ควรใช้ต่อ
ใส่ section "Suggested skills" แนะนำ skill ที่ session ถัดไปน่าจะต้องเรียกใช้ตาม context ที่เหลืออยู่

### 4. ปรับตาม argument ถ้ามี
ถ้าผู้ใช้ระบุ argument มาตอนเรียก (`/handoff <คำอธิบาย>`) ให้ตีความเป็นคำอธิบายว่า session ถัดไปจะ
โฟกัสเรื่องอะไร แล้วปรับเนื้อหาเอกสารให้ตรงกับโฟกัสนั้น

### 5. Self-check: Redact ข้อมูลอ่อนไหวก่อนบันทึก
*หลักการ: การ redact ตรวจสอบได้เองจากข้อความร่างที่เขียนไว้แล้ว ไม่ต้องพึ่งข้อมูลภายนอกเพิ่ม จึงควรไล่เช็คอีกรอบก่อนเขียนไฟล์จริงเสมอ แทนที่จะเชื่อว่าร่างแรกสะอาดแล้ว*
ก่อนบันทึก ให้ไล่ตรวจร่างเอกสารทั้งหมดหาข้อมูลอ่อนไหว เช่น API key, password, token, หรือข้อมูลส่วนตัวที่ระบุตัวตนได้ (PII) — ถ้าเจอให้ลบ/blank ออกก่อน แล้วตรวจซ้ำอีกรอบจนมั่นใจว่าไม่เหลือ ก่อนค่อยไปขั้นตอนบันทึกไฟล์จริง

### 6. บันทึกไฟล์
เซฟไปที่ temp directory ของ OS ผู้ใช้ (`%TEMP%` บน Windows, `$TMPDIR` หรือ `/tmp` บน macOS/Linux) ตามหลักข้อ 3 ของ Core Rules แล้วบอก path ที่บันทึกไว้กับผู้ใช้

## Supporting files
