# 📣 Markdown Callout / Admonition Reference

Callout (GitHub เรียกว่า **Alert**) คือ blockquote ที่ GitHub render เป็นกล่องสีพร้อมไอคอน
ใช้ดึงสายตาไปที่ข้อมูลที่คนอ่านข้ามไม่ได้จริงๆ

README ที่ skill นี้ผลิตออกมามีปลายทางคือ GitHub — **ใช้ GitHub Alert syntax เท่านั้น**
dialect อื่นไม่ต้องพิจารณา (ดูหัวข้อ "ห้ามใช้ dialect อื่น" ท้ายไฟล์)

## เลือกชนิดยังไง

GitHub มี 5 ชนิด คนมักแยก NOTE กับ IMPORTANT ไม่ออก และ WARNING กับ CAUTION ไม่ออก
ตัดปัญหาด้วยการถามคำถามเดียว — **"ถ้าคนอ่านข้ามบรรทัดนี้ไป จะเกิดอะไรขึ้น"** — แล้วไล่บันได
ความเสียหายลงมา ไม่ต้องตีความจาก "ความรู้สึกว่าเรื่องนี้สำคัญแค่ไหน" ซึ่งวัดไม่ได้

| ถ้าข้ามแล้ว... | ใช้ | ตัวอย่าง |
|---|---|---|
| ไม่เกิดอะไร แต่รู้ไว้ดีกว่า | `[!NOTE]` | เวอร์ชัน 2.0 เปลี่ยนชื่อ config file จาก `.apprc` เป็น `app.config.js` |
| พลาดวิธีที่เร็ว/สะดวกกว่า | `[!TIP]` | ใส่ `--watch` แล้วไม่ต้อง restart เองทุกครั้งที่แก้ไฟล์ |
| **มันจะไม่ทำงาน** | `[!IMPORTANT]` | ต้องตั้ง `DATABASE_URL` ก่อนรัน migrate ไม่งั้น command จะ fail |
| **พังแต่แก้กลับได้** | `[!WARNING]` | รันคำสั่งนี้บน production จะ restart service ประมาณ 10 วินาที |
| **เสียข้อมูล / secret หลุด / ย้อนไม่ได้** | `[!CAUTION]` | `--force` ลบ volume ทั้งหมดถาวร กู้คืนไม่ได้ |

สามอันล่างคือเส้นแบ่งที่ต้องแม่น: **ไม่ทำงาน** → **พังแต่แก้ได้** → **ย้อนไม่ได้**

## กฎที่สำคัญที่สุด — ถ้าข้ามแล้วไม่เกิดอะไร แปลว่าไม่ควรเป็น callout

ถ้าคำตอบของคำถามข้างบนคือ *"ก็ไม่เกิดอะไร"* → เขียนเป็นประโยคปกติ หรือลบทิ้ง
**อย่าใส่กล่อง**

callout คือการขัดจังหวะการอ่าน มันได้ผลเพราะมันหายาก README ที่มีกล่องสีทุกหัวข้อ
ให้ผลเท่ากับไม่มีกล่องเลย — สายตาจะเรียนรู้ที่จะข้ามมันทั้งหมด นี่คือเหตุผลเดียวกับที่
SKILL.md กำหนดให้ตัด section ที่ไม่มีเนื้อหาจริงทิ้ง: ของที่ใส่มาเพื่อให้ดูครบ
ทำให้ของที่สำคัญจริงจมหายไป

## Syntax และข้อจำกัด

```markdown
> [!WARNING]
> รันคำสั่งนี้บน production จะ restart service ประมาณ 10 วินาที
> ควรทำนอกเวลาทำการ
```

- บรรทัดแรกมีแค่ `> [!TYPE]` ห้ามเขียนข้อความต่อท้ายบรรทัดเดียวกัน
- ทุกบรรทัดถัดไปต้องขึ้นต้นด้วย `>` — บรรทัดว่าง (ไม่มี `>`) จะจบกล่องทันที
- ชื่อชนิดเป็น **ตัวพิมพ์ใหญ่ทั้งหมด** — `[!note]` ตัวเล็กเป็น syntax ของ Obsidian
  GitHub ไม่รู้จัก จะกลายเป็น blockquote ธรรมดาที่โชว์ `[!note]` เป็นตัวอักษรดิบ
- **ใส่ในตารางไม่ได้** — cell ของ markdown table รับได้แค่ inline element
  ถ้าข้อมูลเตือนอยู่ในตาราง ให้ย้ายออกมาเป็น callout นอกตาราง หรือคงไว้เป็นข้อความในตาราง

## โควตา — 1 อันต่อ section

**หนึ่ง section ใส่ได้มากที่สุด 1 อัน** ไม่จำกัดจำนวนรวมทั้งไฟล์

ถ้ารู้สึกว่า section เดียวต้องเตือน 2 เรื่อง แปลว่าอย่างใดอย่างหนึ่งใน 2 ข้อนี้เกิดขึ้น:
เรื่องหนึ่งไม่ได้สำคัญจริงตามเกณฑ์ข้างบน (ยุบเป็นประโยคปกติ) หรือ section นั้นกำลังทำ
หลายหน้าที่ปนกันจนควรแยกเป็น 2 section

**Sub-folder README แทบไม่ควรมีเลย** — ไม่ใช่เพราะห้าม แต่เพราะ Sub-folder README Pattern
ใน `structure.md` ตัด Installation, Configuration, Deployment, Security ออกไปหมดแล้ว
ซึ่งเป็น section ที่ callout ควรอยู่พอดี ถ้าเขียน sub-folder README แล้วรู้สึกอยากเตือนอะไร
ให้เช็คก่อนว่าเนื้อหานั้นวางถูกที่หรือเปล่า มันมักเป็นของที่ควรอยู่ใน main README

## วางตรงไหนได้ / ไม่ได้

| ✅ เหมาะ | เหตุผล |
|---|---|
| Installation 🚀 | ข้อกำหนดที่คนพลาดบ่อยจนติดตั้งไม่ผ่าน |
| Configuration ⚙️ | การจัดการ secret, ค่าที่ตั้งผิดแล้วพัง |
| API Key / Credentials 🔑 | เตือนเรื่องการ commit key ลง repo |
| Deployment 🐳 | ขั้นตอนที่กระทบ production หรือย้อนไม่ได้ |
| Troubleshooting ⚠️ | ทางแก้ที่มีผลข้างเคียง |

| ❌ ห้าม | เหตุผล |
|---|---|
| ใต้ title ก่อน intro | คนยังไม่รู้ว่าโปรเจกต์นี้คืออะไร เตือนไปก็ไม่มีบริบทให้เข้าใจ |
| ในตาราง | render ไม่ออก (ดูหัวข้อ Syntax) |
| Features ✨ / Usage 🏆 เพื่อความสวย | เป็นการตกแต่ง ไม่ใช่การเตือน — ผิดกฎข้อแรก |
| ติดกัน 2 กล่อง | กลายเป็นบล็อกสียาวๆ ที่ไม่มีอะไรเด่นกว่ากัน |

## ห้ามใส่ emoji ในกล่อง

GitHub วาดไอคอนของแต่ละชนิดให้เองอยู่แล้ว (ℹ️ NOTE, 💡 TIP, ❗ IMPORTANT, ⚠️ WARNING,
🛑 CAUTION) การเติม emoji เข้าไปอีกจะได้ไอคอนซ้อนกัน 2 อันในกล่องเดียว

ข้อนี้ต้องระวังเป็นพิเศษเพราะ convention ของ skill นี้ให้ใส่ emoji หน้าหัวข้อทุกอัน
จนติดเป็นนิสัย — แต่ mapping ใน `emoji.md` ใช้กับ `### H3` **เท่านั้น** ไม่ใช่กับ callout

```markdown
❌ > [!WARNING]
   > ⚠️ รันแล้ว service จะ restart

✅ > [!WARNING]
   > รันแล้ว service จะ restart
```

## ห้ามใช้ dialect อื่น

Admonition มีหลายสำนักและ **ใช้ข้ามกันไม่ได้** — เขียนผิดสำนักจะกลายเป็นข้อความเปล่าๆ
บนหน้า repo ทันที:

| Syntax | ของใคร | ผลบน GitHub |
|---|---|---|
| `> [!NOTE]` | **GitHub** | ✅ กล่องสีพร้อมไอคอน |
| `!!! note` | MkDocs / Material | ❌ ข้อความธรรมดา |
| `::: note` | Docusaurus / VitePress | ❌ ข้อความธรรมดา |
| `> [!note]` ตัวเล็ก | Obsidian | ❌ blockquote ที่โชว์ `[!note]` ดิบ |

ถ้าเจอ README เดิมที่ใช้ dialect อื่นอยู่ ให้แปลงเป็น GitHub syntax ตอน refactor
โดยแมปตามความหมาย ไม่ใช่ตามชื่อ — เช่น `!!! danger` ของ MkDocs สื่อถึงความเสียหาย
ที่ย้อนไม่ได้ ตรงกับ `[!CAUTION]` ไม่ใช่ `[!WARNING]`

## ตัวอย่างเทียบ ดี vs ไม่ดี

**❌ ไม่ดี — เป็นการตกแต่ง ข้ามไปก็ไม่เกิดอะไร**

```markdown
### ✨ Features

> [!NOTE]
> โปรเจกต์นี้รองรับหลายภาษา

- Multi-language support
- Dark mode
```

ข้อความในกล่องซ้ำกับ bullet ข้างล่าง และข้ามไปก็ไม่มีผลอะไร → ลบทิ้ง

**✅ ดี — ข้ามแล้วติดตั้งไม่ผ่านจริง**

````markdown
### 🚀 Installation

> [!IMPORTANT]
> ต้องใช้ Node.js 20 ขึ้นไป เวอร์ชันต่ำกว่านี้ build ไม่ผ่านเพราะใช้ native fetch

```shell
npm install
```
````

**✅ ดี — ระดับ CAUTION เพราะย้อนไม่ได้**

````markdown
### 🐳 Deployment

> [!CAUTION]
> `make reset-db` ลบข้อมูลใน production database ทั้งหมดถาวร ไม่มี backup อัตโนมัติ

```shell
make deploy
```
````
