# ชื่อเทคนิค

**Tool:** ชื่อเต็มของเครื่องมือ · **Level:** 🟢 Basic

## TL;DR
1-2 ประโยค: เทคนิคนี้ทำอะไร แก้ปัญหาอะไร ทำไมถึงคุ้มที่จะจำไว้

## เมื่อไหร่ควรใช้
บริบท/สัญญาณที่บอกว่าควรหยิบเทคนิคนี้มาใช้ (ไม่ใช่ทุกครั้ง — ระบุข้อจำกัดของบริบทด้วย)

## ลำดับการใช้งาน
**ก่อนเทคนิคนี้:** [ชื่อเทคนิค](../folder/other-technique.md) — เหตุผลว่าทำไมต้องทำก่อน
**หลังเทคนิคนี้:** [ชื่อเทคนิค](../folder/other-technique.md) — เหตุผลว่าทำไมมักทำต่อ

ถ้าเทคนิคนี้ไม่มีขั้นก่อน/หลังที่เกี่ยวข้อง ให้ใส่ "ไม่มี" แทน อย่าลบหัวข้อทิ้ง

## วิธีใช้
ขั้นตอนหรือ syntax แบบทำตามได้เลย

1. ...
2. ...

​```bash
# ตัวอย่าง command จริง
​```

## Diagram
ใส่เฉพาะเทคนิคที่มี flow/step ซับซ้อนพอจะได้ประโยชน์จากภาพ — ไม่ต้องบังคับทุกไฟล์
ถ้าไม่มี diagram ให้ลบทั้ง section นี้ทิ้งไปเลย (อย่าเก็บหัวข้อเปล่า)

​```mermaid
flowchart LR
    A[สถานการณ์เริ่มต้น] --> B[ขั้นตอนที่ทำ]
    B --> C[ผลลัพธ์]
​```

## ตัวอย่างการใช้งานจริง
**สถานการณ์:** ...
**สิ่งที่พิมพ์/ทำ:** ...
**ผลที่ได้:** ...

## ข้อควรระวัง
ข้อจำกัด, เคสที่ไม่ควรใช้, side effect ที่เจอมาแล้ว

## อ้างอิง
ลิงก์ doc ต้นทาง หรือที่มาของเทคนิค (ถ้ามี) — ใส่ URL จริงเสมอ ห้ามกุลิงก์
```

## กติกาการตั้งชื่อไฟล์และโฟลเดอร์

- โฟลเดอร์ต่อ 1 tool ใช้ kebab-case slug: `claude-code/`, `claude-design/`, `codex-cli/`, `antigravity-cli/`
  ถ้าผู้ใช้พูดถึง tool ใหม่ที่ยังไม่มีโฟลเดอร์ ให้สร้างโฟลเดอร์ใหม่ตาม slug ที่เหมาะสมได้เลย
- ไฟล์เทคนิคใช้ kebab-case ตาม `title` เช่น `parallel-subagent-dispatch.md`
- ห้ามใช้ชื่อไฟล์ซ้ำในโฟลเดอร์เดียวกัน — ถ้าเทคนิคใกล้เคียงกันอยู่แล้ว ให้เสนอ "อัพเดทไฟล์เดิม" แทนสร้างไฟล์ใหม่

## กติกาเรื่องลิงก์ที่ยังไม่มีไฟล์จริง (stub)

เวลาเขียน/อัพเดทเทคนิคแล้วต้อง link ไปเทคนิคที่ยังไม่มีไฟล์ในโฟลเดอร์ ให้สร้างไฟล์ stub ให้ทันที:

- มี frontmatter ครบ (title/tool/level/tags/added) + หัวข้อ + TL;DR ที่เขียนว่า `> TODO: ยังไม่ได้เขียนรายละเอียด — สร้างจาก link ใน <ชื่อไฟล์ต้นทาง>`
- ที่เหลือ section อื่นปล่อยว่างไว้ก่อนได้ (หรือใส่ `_ยังไม่มีข้อมูล_`)
- ทำแบบนี้เพื่อให้ลิงก์ไม่มีวันพัง และเห็นภาพว่า "รู้ว่าต้องมีเทคนิคนี้" ทั้ง collection ค่อยๆ กลายเป็นกราฟของเทคนิคที่โยงกัน

## กติกาเรื่อง index ต่อโฟลเดอร์

ทุกโฟลเดอร์ต้องมี `README.md` เป็น index ของ tool นั้น — ทุกครั้งที่เพิ่ม/แก้/ลบไฟล์เทคนิคในโฟลเดอร์ ต้อง regenerate README.md ใหม่ทั้งไฟล์ตามรูปแบบ:

```markdown
# เทคนิค — ชื่อเต็มของ Tool

| เทคนิค | Level | Tags | TL;DR |
|---|---|---|---|
| [ชื่อเทคนิค](./file-name.md) | 🟢 Basic | `tag1` `tag2` | สรุปสั้นๆ 1 บรรทัด |
```

เรียงตาม level (basic → intermediate → advanced) แล้วเรียงตามตัวอักษรในแต่ละกลุ่ม ไฟล์ stub (ที่ TL;DR ยังเป็น TODO) ให้ทำเครื่องหมาย 🚧 หน้าชื่อเทคนิคด้วย จะได้รู้ว่ายังไม่สมบูรณ์
