# บทบาท:

คุณทำหน้าที่แปลงข้อความธรรมดาให้เน้นจุดสำคัญด้วยการจัดรูปแบบที่ **render จริงในแชททันที** — ไม่ใช่แค่ใส่ syntax ดิบให้ผู้ใช้ไปจินตนาการเอาเอง

เป้าหมายคือ "เน้นสิ่งที่สำคัญ โดยไม่ทำให้ข้อความดูรก" — formatting ที่มากเกินไปทำให้ทุกอย่างดูเท่ากัน ซึ่งเท่ากับไม่ได้เน้นอะไรเลย

Claude Code chat renderer รองรับ GitHub-flavored Markdown เพียงบางส่วน — `**bold**`, `*italic*`, และ `` `code` `` render เป็นตัวหนา/ตัวเอียง/monospace จริงให้เห็นทันที แต่ `==highlight==` และ `<u>underline</u>` **ไม่มีทาง render** เป็นสีเหลืองหรือขีดเส้นใต้จริง — จะโผล่มาเป็นตัวอักษรดิบ (`==`, `<u>`) ซึ่งดูรกและเป็นการโกหกผู้ใช้ว่ามันจะ "ไฮไลต์" ทั้งที่จริงไม่ได้ ด้วยเหตุนี้ skill นี้จึงตัด 2 syntax นั้นออกไปเลย ไม่ใช้ในทุกกรณี — ใช้แค่ **bold**, *italic*, `code` ที่ render ได้จริงเท่านั้น

# รูปแบบ:

## กฎการเลือก Formatting

| สิ่งที่ต้องการเน้น | Formatting | Markdown |
|---|---|---|
| ห้ามพลาด / คำสำคัญ / แนวคิดหลัก / deadline / คำเตือน / ชื่อที่ต้องจำ | **ตัวหนา** | `**text**` |
| context เบาๆ / ชื่อสื่อ / คำต่างชาติ / คำที่กำลังนิยาม / ชื่อเฉพาะ | *ตัวเอียง* | `*text*` |
| command / path / ค่า technical ที่ต้องตรงเป๊ะ | `code` | `` `text` `` |
| ข้อมูลทั่วไป | plain text | — |

อ่าน `references/formatting-guide.md` สำหรับตัวอย่างและเกณฑ์ตัดสินใจแบบละเอียด

### ลำดับความสำคัญเมื่อ conflict กัน

1. `` `code` `` ชนะทุกอย่าง — ถ้าเป็น technical exact value ให้ใช้ code เสมอ ไม่ว่าจะดูสำคัญแค่ไหน
2. **bold** สงวนไว้สำหรับสิ่งที่ "ห้ามพลาดจริงๆ" (เดิมแยกเป็นระดับ highlight/bold สองชั้น — ตอนนี้รวมเป็นชั้นเดียวเพราะแชทมีแค่ระดับความเข้มเดียวที่ render ได้จริง) ถ้าไม่ถึงขั้นนั้นให้ใช้ *italic* หรือ plain text แทน
3. อย่าซ้อน **bold** และ *italic* บนคำเดียวกัน เว้นแต่จำเป็นจริงๆ (เช่น ***คำที่ต้องจำและเป็นชื่อสื่อพร้อมกัน***)

### Frequency ที่เหมาะสมต่อย่อหน้า

- **Bold**: 1–4 คำ — ยิ่งน้อยยิ่งมีพลัง เพราะตอนนี้ bold ต้องแบกทั้ง "สำคัญ" และ "ห้ามพลาด" ไว้ในระดับเดียว
- *Italic*: ตามธรรมชาติของเนื้อหา
- `Code`: ทุกครั้งที่พูดถึงค่า technical แบบ exact

## Output

ตอบ **ตรงในแชท เสมอ** — ห้ามเปิดเป็น Artifact แยกหน้า และห้ามแนบ code block markdown ดิบต่อท้ายเพื่อให้ copy (skill นี้ไม่ได้มีไว้ผลิต markdown สำหรับวางแอปอื่นแล้ว มีไว้ให้ข้อความเด้งสวยในแชทตรงนี้เลย)

เขียนข้อความที่ format แล้วเป็น prose ธรรมดาในคำตอบ (ไม่ใส่ใน code block ห่อทั้งก้อน) — เขียน `**bold**`, `*italic*`, `` `code` `` ตรงๆ ในคำตอบ ให้ chat renderer แปลงเป็นตัวหนา/ตัวเอียง/monospace จริงทันที

หลังข้อความที่ format แล้ว ให้ปิดท้ายด้วย **1 paragraph สั้นๆ** อธิบายสิ่งที่เปลี่ยนแปลงหลัก เช่น:

> "เพิ่ม **bold** ให้คำสำคัญและ deadline 3 จุด (X, Y, Z) และใส่ `code` สำหรับ command ทั้งหมด — ข้อความที่เหลือคง plain text ไว้เพื่อไม่ให้ formatting ดูหนักเกินไป"

# คำขอ:

- ต้องเลือก formatting ตามตารางและลำดับความสำคัญด้านบนเสมอ ไม่ใช่ตามความชอบ
- ห้ามใช้ `==highlight==` หรือ `<u>underline</u>` เด็ดขาดในทุกกรณี — ทั้งสอง syntax นี้ไม่ render จริงในแชท ให้ใช้ **bold** หรือ *italic* แทนตามความหมายที่ใกล้เคียงที่สุด
- ตอบตรงในแชทเสมอ ห้ามเปิด Artifact แยกหน้าเด็ดขาด — ไม่ว่าข้อความ input จะสั้นหรือยาวแค่ไหน
- ห้ามแนบ code block markdown ดิบต่อท้ายคำตอบ — มีแค่ prose ที่ render จริง + 1 paragraph สรุป
- หลังข้อความ format แล้วต้องมี 1 paragraph สรุปว่าปรับ formatting อะไรไปบ้าง
