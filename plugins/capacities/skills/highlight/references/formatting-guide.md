# Formatting Guide — Chat Rendering

คู่มืออ้างอิงสำหรับตัดสินใจว่าควรใช้ formatting แต่ละแบบเมื่อไหร่และเพราะอะไร

เดิม skill นี้มี 5 ระดับ formatting (bold, italic, code, `==highlight==`, `<u>underline</u>`) ซึ่งอ้างอิงมาจาก
syntax ที่แอป Capacities รองรับ แต่ Claude Code chat renderer render ได้จริงแค่ 3 อย่าง — **bold**, *italic*,
`code` — ส่วน `==highlight==` และ `<u>underline</u>` จะโผล่เป็นตัวอักษรดิบ ไม่ใช่สีเหลืองหรือขีดเส้นใต้จริง
คู่มือนี้จึงรวม 5 ระดับเดิมเหลือ 3 ระดับที่ render ได้จริงทั้งหมด: **highlight (เดิม) รวมเข้ากับ bold**,
**underline (เดิม) รวมเข้ากับ italic**

---

## ตัวหนา `**text**`

**ความหมาย:** "สิ่งนี้ห้ามพลาด ต้องจำไว้" — ครอบคลุมทั้งระดับ "สำคัญ" และ "สำคัญที่สุด" เดิม

ใช้สำหรับ:
- **คำสำคัญ** ที่เป็น core concept ของเนื้อหานั้น เช่น **Machine Learning**, **API Gateway**
- **ชื่อที่ต้องจำ** — ชื่อคน, ชื่อโปรแกรม, ชื่อบริษัท, ชื่อโปรเจกต์
- **ข้อสรุปหลัก** หรือ takeaway ของย่อหน้า
- **ตัวเลขสำคัญ** เช่น เป้าหมาย, งบประมาณ, ขีดจำกัด
- **คำเตือน**, **ข้อควรระวัง**, **deadline** หรือ **action item** ที่ถ้าพลาดจะมีผลเสีย (เดิมคือ `==highlight==`)

อย่าใช้สำหรับ:
- คำทั่วไปที่ไม่ใช่ concept หลัก (จะทำให้ bold เจือจาง)
- ทุกประโยคในย่อหน้า — ถ้า bold ทุกอย่างเท่ากับไม่ได้ bold อะไรเลย

เพราะ bold ตอนนี้แบกทั้งสองความหมาย (สำคัญ + ห้ามพลาด) ไว้ในระดับเดียว ต้อง**เข้มงวดกว่าเดิม**กับความถี่ —
1–4 คำต่อย่อหน้าเท่านั้น ไม่ใช่ทุกคำที่ดูสำคัญ

**ตัวอย่าง:**

> ข้อความเดิม: "kubernetes คือระบบจัดการ container ที่ google พัฒนาขึ้น ต้องส่งรายงานภายในวันศุกร์นี้ 17:00 มิฉะนั้นโปรเจกต์จะล่าช้า"
>
> หลัง format: "**Kubernetes** คือระบบจัดการ container ที่ **Google** พัฒนาขึ้น ต้องส่งรายงานภายใน **วันศุกร์นี้ 17:00** มิฉะนั้นโปรเจกต์จะล่าช้า"

## ตัวเอียง `*text*`

**ความหมาย:** "บริบท การอ้างอิง หรือคำที่กำลังถูกนิยาม/สังเกต" — ครอบคลุมทั้ง italic เดิมและ underline เดิม

ใช้สำหรับ:
- *ชื่อหนังสือ*, *บทความ*, *เพลง*, *ภาพยนตร์* — สื่อทุกประเภท
- *คำภาษาต่างประเทศ* ที่ยังไม่ได้ทับศัพท์ไทยหรือใช้ทั่วไป
- *นิยามคำแรก* — ครั้งแรกที่นำเสนอคำศัพท์พร้อมอธิบาย (เดิมส่วนหนึ่งคือ `<u>underline</u>`)
- *ชื่อเฉพาะที่พิเศษ* ที่ไม่ใช่ technical term เช่น ชื่อโปรเจกต์, ชื่อทีม (เดิมคือ `<u>underline</u>`)
- *การเน้นเบาๆ* ที่ไม่ถึงขั้นต้องตัวหนา เช่น "ควรทำ *ก่อน* เสมอ"

อย่าใช้สำหรับ:
- สิ่งที่ต้องการเน้นแบบ "ห้ามพลาด" → ใช้ **bold** แทน
- ชื่อ command หรือ technical string → ใช้ `code` แทน

**ตัวอย่าง:**

> "อ่านหนังสือ *Atomic Habits* แล้วนำแนวคิด *habit stacking* มาใช้ — *Zero-shot learning* คือการที่โมเดล AI ทำงานกับ task ที่ไม่เคยเห็นตัวอย่างมาก่อน"

## Code `` `text` ``

**ความหมาย:** "ค่าที่ต้องใช้แบบตรงๆ ห้ามเปลี่ยน"

ใช้สำหรับ:
- `คำสั่ง` และ flags เช่น `git commit`, `npm install --save-dev`
- `file path` และ directory เช่น `/etc/nginx/nginx.conf`, `~/Downloads/`
- `ชื่อตัวแปร`, `function`, `class` ในโค้ด
- `ค่า config` หรือ `environment variable` เช่น `NODE_ENV=production`
- `ค่าที่ต้องกรอกแบบตรงๆ` เช่น `true`, `null`, `200`, `utf-8`

สำหรับ code หลายบรรทัด ใช้ code block:

````
```python
def hello():
    return "world"
```
````

**ตัวอย่าง:**

> "รัน `docker compose up -d` แล้วเช็ก log ด้วย `docker logs -f app`"

## Quick Decision Table

```
ถามตัวเองว่า...                              → ใช้
────────────────────────────────────────────────────
มันคือ command, path, หรือ exact value?      → `code`
ห้ามพลาด / เป็น concept หลักที่ต้องจำ?       → **bold**
มันคือชื่อสื่อ, คำต่างชาติ, หรือกำลังนิยาม?  → *italic*
อื่นๆ                                        → plain text
```

## สัญญาณเตือนว่า Format มากเกินไป

- Bold มากกว่า 4 คำในย่อหน้าเดียว
- ใช้หลาย formatting บนคำเดียวกัน (เช่น **`code`** หรือ ***bold italic***) โดยไม่จำเป็น
- ทุกประโยคมี formatting — ถ้าทุกอย่างเด่น ไม่มีอะไรเด่นจริงๆ
- เขียน `==text==` หรือ `<u>text</u>` หลุดออกมา — สองอย่างนี้ตัดออกจาก skill แล้ว ห้ามใช้อีก
