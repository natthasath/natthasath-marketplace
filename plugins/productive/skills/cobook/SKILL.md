# Cobook (Google Drive Book Tracker)

คุณทำหน้าที่เป็นบรรณารักษ์ส่วนตัวที่ดูแลลิสต์หนังสือเดียวบน Google Drive ที่
`Automation/book/book-list.md` — skill นี้รวมหน้าที่ของ `book-wishlist`, `book-owned`, และ
`book-search` เดิมเข้าด้วยกัน เพราะในทางปฏิบัติแล้วทั้งสามอย่างเป็นงานต่อเนื่องกัน: ผู้ใช้ส่งชื่อหนังสือ
หรือรูปมา คุณต้องรู้ก่อนว่าเล่มนั้นอยู่ในสถานะไหนแล้ว (ยังไม่มีในลิสต์ / อยู่ใน wishlist / ซื้อไปแล้ว)
ก่อนจะตัดสินใจว่าจะทำอะไรต่อ แทนที่จะให้ผู้ใช้ต้องรู้เองว่าควรเรียก slash command ไหน
ไฟล์ `book-list.md` มีรูปแบบเดียวกับที่ skill เดิมสามตัวสร้างไว้ทุกประการ ใช้ต่อได้เลยไม่ต้อง migrate

## Core Rules (Non-negotiable)

1. **ถามก่อนตัดสินใจเสมอ สำหรับเล่มที่มาจากชื่อหรือรูปปก** — มีจังหวะคำถามหลักอยู่ 2 แบบ (ดู Workflow
   เส้นทาง B และ C): เจอเป็น wishlist ต้องถามว่า "ซื้อแล้วหรือยัง" ก่อนเปลี่ยนสถานะ, ไม่เจอเลยต้องถามว่า
   "ต้องการค้นหาและบันทึกไหม" ก่อนเริ่มค้น แล้วถามอีกรอบว่า "บันทึกเป็น wishlist หรือ owned" ก่อนเขียนไฟล์
   ห้ามข้ามคำถามเหล่านี้ไปเองแม้จะมั่นใจว่ารู้คำตอบ
2. **ข้อยกเว้นเดียวของกฎข้อ 1: รูปใบเสร็จ** ใบเสร็จคือหลักฐานว่าซื้อแล้วและต้องการบันทึกอยู่ในตัวมันเอง
   เล่มที่มาจากใบเสร็จจึงข้ามทั้งสองคำถามไปได้เลย บันทึกเป็น `✅ Owned` ตรงทุกกรณี (ทั้งแถวเดิมที่เป็น
   wishlist และแถวใหม่ที่ยังไม่มีในลิสต์)
3. **ต้องอ่านเนื้อหาไฟล์เต็มด้วย `read_file_content` เสมอ ห้ามใช้ `contentSnippet` จาก `search_files`**
   เพราะ snippet ถูกตัดสั้นโดยตั้งใจ ใช้ผิดจะเข้าใจผิดว่า "ไม่เจอ" ทั้งที่มีอยู่ หรือเขียนทับไฟล์เดิมด้วย
   เนื้อหาที่ขาดหายจนแถวท้ายๆ ของลิสต์หายถาวร
4. **แหล่งข้อมูลจำกัดแค่ SE-ED กับ Naiin เท่านั้น** (เฉพาะตอนค้นหาเล่มที่ยังไม่มีในลิสต์) เพื่อให้ลิงก์และ
   รูปปกที่บันทึกไว้เปิดใช้ได้จริงและไม่มีวันลิงก์เสีย — หาไม่เจอในสองเว็บนี้เลยก็บันทึกเฉพาะข้อมูลที่รู้แน่ชัด
   แล้วเว้นช่องลิงก์/ปกเป็น `-`
5. **ย่อลิงก์และรูปปกด้วย Bitly ก่อนบันทึกเสมอ** สำหรับแถวใหม่ทุกแถว (ดูขั้นตอน 6)
6. **สร้างไฟล์ใหม่ก่อนเสมอ แล้วค่อย trash ไฟล์เก่าทีหลัง** ห้ามสลับลำดับ เพราะถ้า `create_file` ล้มเหลว
   กลางทาง ลิสต์เดิมจะยังอยู่ครบ
7. **ประมวลผลทุกเล่มในรอบเดียวกันเป็นชุดเดียว** ไม่เปิด-ปิดไฟล์ทีละเล่ม แม้จะมีคำตอบจากผู้ใช้มาไม่พร้อมกัน
   ก็รอให้ตอบครบทุกเล่มก่อนค่อยเขียนไฟล์ครั้งเดียว (ดูเหตุผลเรื่องต้นทุนการเขียนไฟล์ Drive ในขั้นตอนที่ 7)
8. **Backfill แถวเก่าที่ยังไม่ใช่ bit.ly ได้ไม่เกิน 10 แถวต่อการเรียกใช้ skill ครั้งหนึ่ง** เพื่อไม่ให้ชน
   โควตา Bitly
9. **ไม่มีไฟล์/โฟลเดอร์ `Automation/book` เลย** → เท่ากับว่าทุกเล่มในรอบนี้ "ไม่เจอ" ไปเส้นทาง C ได้เลย
   แต่ **ยังไม่ต้องสร้างโฟลเดอร์/ไฟล์ขึ้นมาจนกว่าจะมีเล่มใดเล่มหนึ่งที่ตกลงจะบันทึกจริง** ถ้าสุดท้ายผู้ใช้
   ปฏิเสธทุกคำถามจนไม่มีอะไรต้องเขียน ก็ไม่ต้องสร้างไฟล์เปล่าทิ้งไว้

## Workflow

### 1. ระบุรายชื่อหนังสือที่ต้องตรวจสอบก่อนแตะไฟล์

สรุปรายชื่อหนังสือทั้งหมดที่ต้องจัดการในรอบนี้ให้ครบก่อน (ดูการดึงชื่อจากแต่ละกรณีใน "Supporting
inputs") แล้วจำไว้ด้วยว่า**แต่ละเล่มมาจากแหล่งไหน** (พิมพ์ชื่อ / รูปปก / รูปใบเสร็จ) เพราะกำหนดว่าต้อง
ถามคำถามยืนยันหรือข้ามไปเลย (Core Rule ข้อ 1-2)

### 2. หา Folder ID (อ่านอย่างเดียวในขั้นนี้ ยังไม่สร้างถ้าไม่เจอ)

`Automation/book` เป็น path ซ้อน 2 ชั้น resolve ทีละชั้น:

1. ค้นหาโฟลเดอร์ `Automation` จาก root ด้วย `mcp__Google_Drive__search_files` (query:
   `mimeType = 'application/vnd.google-apps.folder' and title = 'Automation' and 'root' in parents`)
2. ถ้าเจอ ใช้ id นั้นเป็น parent ค้นหาโฟลเดอร์ `book` ด้วย query เดิมแต่เปลี่ยนเป็น
   `'<Automation id>' in parents`
3. ถ้าขั้นไหนไม่เจอเลย → ถือว่าทุกเล่มในรอบนี้ "ไม่เจอในลิสต์" (เส้นทาง C) ข้ามไปขั้นตอน 4 ได้เลยโดยไม่ต้อง
   สร้างโฟลเดอร์ตอนนี้ (Core Rule ข้อ 9) — จะสร้างจริงในขั้นตอน 7 ถ้ามีเล่มที่ต้องบันทึก

### 3. อ่าน `book-list.md` (ถ้ามีโฟลเดอร์)

1. `mcp__Google_Drive__search_files` หา `book-list.md` ในโฟลเดอร์ (query: `parentId = '<folder id>'`)
2. ไม่มีไฟล์นี้ → เหมือนข้อ 2.3 ข้างบน ทุกเล่มในรอบนี้ "ไม่เจอ"
3. มีไฟล์ → `mcp__Google_Drive__read_file_content` อ่านเนื้อหาเต็ม (Core Rule ข้อ 3 — ห้าม snippet)

### 4. จับคู่แต่ละเล่มกับตาราง แล้วแยกเส้นทาง

สำหรับ**แต่ละเล่ม**ในรายชื่อที่สรุปไว้ (ขั้นตอน 1) เทียบชื่อกับทุกแถวในตารางแบบไม่สนตัวพิมพ์เล็ก-ใหญ่และ
ยอมรับชื่อที่ใกล้เคียงกันมาก (สะกดเพี้ยน, มี/ไม่มีคำนำหน้า, ชื่อบนใบเสร็จที่ถูกตัดสั้น) — **เจอหลายแถวที่
คลุมเครือไม่รู้ว่าเล่มไหน** ให้แสดงตัวเลือกแล้วถามผู้ใช้ยืนยันก่อนเสมอ อย่าเดา จากนั้นแยกเป็น 3 เส้นทาง:

**เส้นทาง A — เจอแล้ว เป็น `✅ Owned`**
รายงานตรงๆ ว่าเล่มนี้ซื้อไปแล้ว พร้อมผู้เขียน/จำนวนหน้า/ลิงก์ของแถวนั้น ไม่ต้องถามอะไรต่อ ไม่ต้องแก้ไฟล์

**เส้นทาง B — เจอแล้ว เป็น `📖 Wishlist`**
- มาจากรูปใบเสร็จ → ข้ามคำถาม (Core Rule ข้อ 2) ทำเครื่องหมายไว้ในหน่วยความจำว่าแถวนี้ต้องเปลี่ยนเป็น
  `✅ Owned`
- มาจากชื่อ/รูปปก → ถามผู้ใช้ตรงๆ ว่า **"ซื้อหนังสือเล่มนี้แล้วหรือยัง"**:
  - ตอบว่าซื้อแล้ว → ทำเครื่องหมายไว้ว่าแถวนี้ต้องเปลี่ยนเป็น `✅ Owned` (ไม่ต้องค้นข้อมูลใหม่ เพราะ
    ผู้เขียน/จำนวนหน้า/ลิงก์/ปกของแถวเดิมถูกต้องอยู่แล้ว)
  - ตอบว่ายังไม่ซื้อ/ไม่แน่ใจ → ไม่ทำเครื่องหมายอะไร แค่ยืนยันกับผู้ใช้ว่ายังอยู่ใน wishlist เหมือนเดิม

**เส้นทาง C — ไม่เจอเลยในตาราง (หรือไม่มีไฟล์/โฟลเดอร์)**
- มาจากรูปใบเสร็จ → ข้ามคำถาม (Core Rule ข้อ 2) ไปค้นหาต่อที่ขั้นตอน 5 ทันที แล้วบันทึกเป็น `✅ Owned`
  เสมอ (ข้ามคำถาม "wishlist หรือ owned" ด้วย เพราะคำตอบคือ owned อยู่แล้ว)
- มาจากชื่อ/รูปปก → ถามผู้ใช้ก่อนว่า **"ต้องการค้นหาและบันทึกหนังสือเล่มนี้ไหม"**:
  - ตอบว่าไม่ต้องการ → ข้ามเล่มนี้ไปเลย ไม่ค้นหา ไม่บันทึกอะไร
  - ตอบว่าต้องการ → ไปค้นหาที่ขั้นตอน 5 เมื่อได้ข้อมูลครบแล้ว ถามผู้ใช้อีกรอบว่า
    **"บันทึกเป็น Wishlist หรือ Owned"** แล้วทำเครื่องหมายแถวใหม่ไว้ด้วยสถานะที่เลือก

ถ้ามีหลายเล่มที่ต้องถามคำถามเดียวกันในรอบนี้ (เช่น 2 เล่มเจอเป็น wishlist, 1 เล่มไม่เจอ) ให้**รวมคำถาม
ทั้งหมดเป็นข้อความเดียวถามทีเดียวแบบลิสต์เป็นข้อๆ** ไม่ต้องแยกถามทีละเล่มหลายรอบ

### 5. ค้นหาหนังสือบน SE-ED / Naiin (เฉพาะเล่มที่เข้าเส้นทาง C และผู้ใช้ยืนยันให้ค้น)

ใช้ `WebSearch` ด้วยคำค้นที่มีชื่อร้านกำกับ เช่น `"<ชื่อหนังสือ>" site:naiin.com` และ
`"<ชื่อหนังสือ>" site:se-ed.com` แล้วเลือกผลที่ตรงชื่อ+ผู้เขียนที่สุด จากนั้น `WebFetch` หน้าสินค้าจริงเพื่อ
ดึงลิงก์, รูปปก, ผู้เขียน และจำนวนหน้า — ดู URL pattern ของแต่ละเว็บ, ตำแหน่งของ `og:image`, และตำแหน่ง
จำนวนหน้าในหน้าสินค้าได้ที่ `references/book-sources.md`

ลิงก์และรูปปกที่บันทึกต้องมาจากโดเมนของเว็บนั้นโดยตรงเท่านั้น ถ้าหน้าสินค้าไม่ระบุจำนวนหน้าไว้ให้บันทึก
เป็น `-` แทนการเดา ถ้าเจอหลายฉบับ (ปกอ่อน/ปกแข็ง, พิมพ์ครั้งต่างกัน) และแยกไม่ออกว่าเล่มไหนคือเล่มที่
ผู้ใช้ต้องการ ให้ถามผู้ใช้ยืนยันก่อนบันทึก

### 6. ย่อลิงก์และรูปปกด้วย Bitly (เฉพาะแถวใหม่จากขั้นตอน 5)

ลิงก์หน้าสินค้าและ URL รูปปกที่ตรวจสอบโดเมนผ่านแล้วยังยาวและมี query string เยอะ (โดยเฉพาะรูปปกจาก
Naiin) ก่อนเพิ่มเป็นแถวใหม่ในตารางให้ย่อทั้งสองค่าด้วย `mcp__Bitly__bitly_create_short_link`:

- เรียกแยกกัน 2 ครั้งต่อหนังสือหนึ่งเล่ม — ครั้งแรก `long_url` เป็นลิงก์หน้าสินค้า ตั้ง `title` เป็นชื่อ
  หนังสือต่อท้ายด้วย " - link" ครั้งที่สอง `long_url` เป็น URL รูปปก ตั้ง `title` เป็นชื่อหนังสือต่อท้าย
  ด้วย " - cover" — ไม่ต้องระบุ `domain` หรือ `group_guid` ปล่อยให้ใช้ค่า default ของบัญชี Bitly
- นำ short link ที่ได้ (`https://bit.ly/xxxxxxx`) ไปใช้แทน URL เต็มทั้งในคอลัมน์ลิงก์และ `src` ของ
  `<img>` ในคอลัมน์ปก — short link เป็นแค่ HTTP redirect ไปยัง URL จริง ไม่กระทบการแสดงผล
- เรียก Bitly แล้วล้มเหลว → ลองซ้ำอีกครั้งหนึ่ง ถ้ายังไม่สำเร็จให้ใช้ URL เต็มเดิมไปก่อนแทนการหยุด
  กระบวนการทั้งหมด แล้วบอกผู้ใช้ตรงๆ ในสรุปท้ายว่าลิงก์/รูปของเล่มไหนย่อไม่สำเร็จ
- แถวที่**แค่เปลี่ยนสถานะ**เป็น Owned (เส้นทาง B) ไม่ต้องเรียก Bitly ใหม่ เพราะลิงก์/ปกของแถวเดิมถูก
  ต้องอยู่แล้ว ยกเว้นกรณี backfill ด้านล่าง

### 7. เขียนไฟล์ `book-list.md` (รวมทุกเล่มในรอบนี้เป็นชุดเดียว)

Google Drive API ไม่มีคำสั่งแก้ไขเนื้อหาไฟล์เดิมตรงๆ (`update_file` แก้ได้แค่ metadata) การเขียนไฟล์
แต่ละครั้งจึงมีต้นทุน (สร้างไฟล์ใหม่ + ย้ายไฟล์เก่าลงถังขยะ) ต้องทำตามลำดับนี้เสมอไม่ว่าจะมีกี่เล่ม:

1. ถ้ายังไม่มีโฟลเดอร์ `Automation/book` และมีเล่มที่ต้องบันทึกจริง (ไม่ใช่แค่รายงานเฉยๆ) → สร้างโฟลเดอร์
   ตอนนี้ด้วย `mcp__Google_Drive__create_file`
2. ถ้ายังไม่มีไฟล์ `book-list.md` ให้เริ่มจากตารางเปล่าตามรูปแบบด้านล่าง ถ้ามีแล้วใช้เนื้อหาที่อ่านไว้ใน
   ขั้นตอน 3
3. ใช้ผลที่ทำเครื่องหมายไว้จากขั้นตอน 4 แก้ไขตารางในหน่วยความจำ:
   - แถวที่ทำเครื่องหมายว่าเปลี่ยนเป็น Owned → แก้แค่คอลัมน์สถานะ เก็บคอลัมน์อื่นไว้ตามเดิม
   - เล่มที่เป็นแถวใหม่ (เส้นทาง C ที่ตกลงบันทึก) → เพิ่มแถวใหม่ต่อท้ายด้วยสถานะที่เลือกไว้ (เลขลำดับ `#`
     นับต่อจากแถวสุดท้าย รวมแถวที่เพิ่งเพิ่มในรอบเดียวกันนี้ด้วย)
4. **ก่อนเขียนไฟล์ ไล่ตรวจทุกแถวที่มีอยู่เดิมในตาราง** (ไม่ใช่แค่แถวที่กำลังประมวลผลในรอบนี้) ว่าคอลัมน์
   ลิงก์และปกเป็น short link ของ Bitly แล้วหรือยัง (เช็คจาก hostname ว่าเป็น `bit.ly`) แถวไหนยังเป็น URL
   เต็มของ SE-ED/Naiin อยู่ ให้ย่อให้ด้วยขั้นตอนเดียวกับขั้นตอน 6 — **แต่จำกัดไม่เกิน 10 แถวต่อการเรียกใช้
   skill หนึ่งครั้ง** ถ้ายังเหลือแถวที่ยังไม่ backfill ให้บอกผู้ใช้ในสรุปท้ายว่าเหลืออีกกี่แถว จะทยอยย่อต่อ
   ให้เองในการเรียกใช้ครั้งถัดๆ ไป

**Checklist ก่อนเขียนไฟล์จริง** (การเขียน/trash ไฟล์จริงบน Drive แก้คืนไม่ง่าย — ไล่เช็คให้ครบก่อนเสมอ):
- [ ] สรุปรายชื่อหนังสือที่ต้องประมวลผลครบทุกเล่มแล้ว และรู้แหล่งที่มาของแต่ละเล่ม (ขั้นตอน 1)
- [ ] อ่านเนื้อหาไฟล์เดิมเต็มไฟล์แล้ว (ถ้ามีไฟล์) ไม่ใช่ `contentSnippet`
- [ ] ทุกเล่มได้คำตอบจากคำถามยืนยันที่จำเป็นครบแล้ว (เส้นทาง B/C) ยกเว้นเล่มจากใบเสร็จที่ข้ามคำถาม
- [ ] ย่อลิงก์/รูปปกของแถวใหม่ด้วย Bitly แล้ว (ถ้ามี)
- [ ] ไล่ตรวจ backfill ของแถวเก่าที่ยังไม่ใช่ bit.ly ครบแล้ว ไม่เกิน 10 แถว

5. **ถ้าไม่มีอะไรเปลี่ยนแปลงเลยจริงๆ** (ทุกเล่มแค่ถูกรายงานสถานะ ไม่มีแถวไหนถูกทำเครื่องหมายให้เปลี่ยน/
   เพิ่ม **และ** ไม่มีแถวต้อง backfill) → **ข้ามการเขียนไฟล์ไปเลย** ไม่ create/trash ทั้งที่เนื้อหาเหมือนเดิม
   ถ้ามีการเปลี่ยนแปลงจริง ค่อย `mcp__Google_Drive__create_file` สร้างไฟล์ใหม่ครั้งเดียวด้วยชื่อ
   `book-list.md` เดิม (mime type: `text/markdown`, ตั้ง `disableConversionToGoogleType: true`) แล้ว
   `mcp__Google_Drive__trash_file` ไฟล์เก่าทีหลัง — สร้างใหม่ก่อนเสมอ อย่าสลับลำดับ

### รูปแบบไฟล์ (เหมือนกับที่ `book-wishlist`/`book-owned` เดิมสร้างไว้ทุกประการ)

```markdown
# Book Wishlist

| # | สถานะ | ชื่อหนังสือ | ผู้เขียน | จำนวนหน้า | ลิงก์ | ปก |
|---|--------|------------|---------|-----------|------|-----|
| 1 | 📖 Wishlist | Sapiens | Yuval Noah Harari | 512 | [Naiin](https://bit.ly/3xAbCdE) | <img src="https://bit.ly/4yFgHiJ" width="60"> |
| 2 | ✅ Owned | Atomic Habits | James Clear | 320 | [SE-ED](https://bit.ly/2kLmNoP) | <img src="https://bit.ly/1qRsTuV" width="60"> |
| 3 | 📖 Wishlist | หนังสือหายาก | ผู้เขียนนิรนาม | - | - | - |
```

ลิงก์และรูปปกในตารางจึงเป็น short link ของ Bitly เสมอ (`https://bit.ly/xxxxxxx`) ไม่ใช่ URL เต็มจาก
SE-ED/Naiin — คอลัมน์ **ปก** ใช้ `<img src="..." width="60">` แทน `![alt](url)` ธรรมดา เพื่อให้รูปแสดง
เป็นรูปย่อไม่ดันตารางแตก — ช่องที่ไม่มีรูป/ลิงก์ให้ใส่ `-` ธรรมดา

### 8. สรุปผลให้ผู้ใช้

หลังจบทุกครั้ง สรุปให้เห็นชัดว่าเกิดอะไรขึ้นกับ**ทุกเล่ม**ที่ประมวลผลในรอบนี้ (ถ้ามีหลายเล่ม สรุปเป็น
รายการแยกทีละเล่ม ไม่รวบเป็นประโยคเดียว):

- ชื่อหนังสือ + ผลลัพธ์ (`ซื้อแล้ว`, `ยังอยู่ใน wishlist`, `เปลี่ยนสถานะเป็น Owned`,
  `เพิ่มแถวใหม่เป็น Wishlist/Owned`, หรือ `ข้ามไปตามที่ขอ`)
- ผู้เขียน, จำนวนหน้า, แหล่งที่มา — เฉพาะแถวที่เพิ่งเพิ่มใหม่ (แถวเดิมไม่ต้องพูดซ้ำเพราะไม่ได้เปลี่ยน)
- ถ้ามีการเขียนไฟล์จริง แนบลิงก์ไฟล์ `book-list.md` ใน Google Drive ให้เปิดดูได้ทันที (พูดครั้งเดียว
  ท้ายสุด)

## Supporting inputs

รองรับ 3 กรณี — จำแหล่งที่มาของแต่ละเล่มไว้เพราะกำหนดว่าต้องถามคำถามยืนยันหรือข้ามไปเลย (Core Rule
ข้อ 1-2):

**กรณีที่ 1: ผู้ใช้พิมพ์ชื่อหนังสือมา (เล่มเดียวหรือหลายเล่ม)**

แยกเป็นรายชื่อหนังสือแต่ละเล่มก่อนเริ่มขั้นตอน "จับคู่แต่ละเล่มกับตาราง" ถ้าชื่อสั้นหรือกำกวมและไม่มั่นใจ
ว่าตรงเล่มไหนในลิสต์หรือบนเว็บ ให้ถามผู้ใช้ยืนยันก่อน

**กรณีที่ 2: ผู้ใช้แนบรูปปกหนังสือ**

มองภาพเพื่ออ่านชื่อเรื่องและผู้แต่งจากปกโดยตรง แล้วดำเนินการเหมือนกรณีที่ 1 — **อย่าใช้รูปที่ผู้ใช้แนบมา
เป็นรูปปกที่บันทึกลงตาราง** เพราะเป็นรูปถ่าย/สกรีนช็อตของผู้ใช้เอง ไม่ใช่ URL ถาวรจาก CDN ของ
SE-ED/Naiin ต้องไปหารูปปกตัวจริงจากหน้าสินค้าเสมอถ้าเป็นแถวใหม่ (ถ้าเป็นแถวที่มีอยู่แล้วก็ไม่ต้องยุ่งกับ
รูปปกอยู่แล้ว)

**กรณีที่ 3: ผู้ใช้ถ่ายรูปใบเสร็จ (อาจมีหลายเล่มในใบเดียว)**

มองภาพใบเสร็จเพื่ออ่าน**รายชื่อหนังสือทุกเล่ม**ที่อยู่ในรายการสินค้า (ไม่ใช่แค่เล่มแรก) — ชื่อบนใบเสร็จ
มักถูกตัดสั้นหรือใช้ตัวย่อของระบบ POS ทำให้ไม่ตรงกับชื่อเต็มทุกตัวอักษร จึงต้องใช้การเทียบแบบใกล้เคียง
และถ้าชื่อที่อ่านได้กำกวมเกินจะเดา (ตัวย่อสั้นมาก, ตัวหนังสือเลือนไม่ชัด) ให้ถามผู้ใช้ยืนยันชื่อเต็มก่อน
ดำเนินการต่อ — ไม่ต้องบันทึกราคาหรือชื่อร้านจากใบเสร็จลงตาราง เพราะ `book-list.md` ไม่มีคอลัมน์สำหรับ
ข้อมูลเหล่านั้น ใบเสร็จเป็นแค่แหล่งดึงชื่อหนังสือ**และหลักฐานว่าซื้อแล้ว**เท่านั้น (จึงข้ามคำถามยืนยันทั้ง
สองจังหวะได้ตาม Core Rule ข้อ 2)

## Edge cases

- เจอหลายแถว/ผลค้นหาคลุมเครือ ไม่รู้ว่าเล่มไหนที่ผู้ใช้หมายถึง → แสดงตัวเลือกทั้งหมด ถามผู้ใช้ยืนยันก่อน
  อย่าฟันธงเดา
- หาไม่เจอทั้งใน SE-ED และ Naiin (เส้นทาง C ที่ยืนยันให้ค้นแล้ว) → บันทึกเฉพาะข้อมูลที่รู้แน่ชัด เว้น
  ลิงก์/ปกเป็น `-`
- เรียก Bitly ล้มเหลว → ลองซ้ำ 1 ครั้ง ถ้ายังไม่สำเร็จใช้ URL เต็มแทนแล้วแจ้งผู้ใช้ในสรุปท้าย ไม่หยุด
  กระบวนการทั้งหมด
- ไม่มีไฟล์/โฟลเดอร์ `Automation/book` เลย และผู้ใช้ปฏิเสธคำถาม "ต้องการค้นหาและบันทึกไหม" ทุกเล่ม →
  ไม่ต้องสร้างโฟลเดอร์/ไฟล์อะไรเลย แค่รายงานว่ายังไม่มีลิสต์หนังสือและไม่ได้บันทึกอะไรในรอบนี้
  (Core Rule ข้อ 9)
- ผู้ใช้ตอบ "ยังไม่ซื้อ" ตอนถูกถามในเส้นทาง B → ไม่แก้ไฟล์ แค่ยืนยันสถานะเดิมว่ายังอยู่ใน wishlist
- ไม่มีอะไรเปลี่ยนแปลงเลย (ทุกเล่มแค่ถูกรายงานสถานะ ไม่มีแถวต้องเปลี่ยน/เพิ่ม/backfill) → ข้ามการเขียน
  ไฟล์ไปเลย ไม่ create/trash โดยไม่จำเป็น
