# Chat/Task Title Generator

claude.ai เก็บ Chat และ Task ไว้เป็น list ยาวๆ ที่ default ชื่อว่า "New chat" หรือตัดมาจากข้อความแรกแบบดิบๆ
พอผ่านไปเป็นสัปดาห์หรือเป็นเดือน ผู้ใช้จำไม่ได้แล้วว่าแชทไหนคือแชทไหน และ search ด้วย keyword ก็เจอยาก
งานของ skill นี้คือย่อคำอธิบายสั้นๆ ของผู้ใช้ให้เหลือ "ชื่อเดียว" ที่กระชับ เจาะจง และมี keyword ที่คนในอนาคต
(รวมถึงตัวผู้ใช้เอง) จะพิมพ์ค้นหาจริงๆ — ไม่ใช่แค่สรุปประโยคให้สั้นลง

## Core Rules

1. **ตอบชื่อเดียวที่ดีที่สุด** ไม่ต้องเสนอหลายตัวเลือกให้เลือก — หน้าที่ของ skill นี้คือตัดสินใจแทนผู้ใช้
2. **ชื่อเป็นภาษาอังกฤษเสมอ** แม้คำอธิบายที่ได้รับจะเป็นภาษาไทย เหตุผล: อังกฤษเรียงตัวอักษรและค้นหาได้สม่ำเสมอกว่า ไม่มีปัญหาตัดคำภาษาไทยตอน search บน claude.ai
3. **ยาวไม่เกิน 8 คำ** นับเฉพาะส่วนชื่อ ไม่นับ prefix ในวงเล็บเหลี่ยม
4. **ขึ้นต้นด้วย `[Category]` เสมอ** หนึ่งคำ ขึ้นต้นด้วยตัวใหญ่ (Title Case) ดูหมวดหมู่แนะนำใน Workflow ข้อ 3
5. **ต้องมีชื่อเฉพาะของสิ่งที่กำลังทำอยู่จริง** (ชื่อระบบ, เทคโนโลยี, โปรเจกต์, service) ไม่ใช่แค่คำกริยากว้างๆ — `[Debug] Node.js Express Memory Leak in Docker` ใช้ได้, `[Debug] Fix a Bug` ใช้ไม่ได้เพราะ search แล้วแยกจากแชทอื่นไม่ออก
6. **ห้าม copy ประโยคของผู้ใช้มาทั้งดุ้น** ให้กลั่นเอาแก่นที่ search เจอ ไม่ใช่แปลตรงตัว

## Workflow

### 1. อ่านคำอธิบายที่ได้รับ
คำอธิบายมาจาก argument ที่พิมพ์ต่อท้าย `/rename` ถ้าผู้ใช้เรียก `/rename` เปล่าๆ ไม่มี argument ให้ถามสั้นๆ ว่ากำลังจะทำอะไร ก่อนตั้งชื่อ — อย่าทายมั่ว

### 2. แยกองค์ประกอบ
จากคำอธิบาย หาสามอย่างนี้:
- **ประเภทงาน** (category) — กำลังทำอะไรในเชิง workflow (debug, สร้าง, ออกแบบ, สรุป, ฯลฯ)
- **ตัวจริงที่เกี่ยวข้อง** (subject) — ชื่อระบบ/เทคโนโลยี/โปรเจกต์/ไฟล์ที่เจาะจง นี่คือส่วนที่ทำให้ search เจอ
- **ตัวขยายที่ช่วยแยกความกำกวม** (ถ้ามี) — เช่น environment, เวอร์ชัน, ทีม, ไตรมาส ที่ช่วยแยกจากแชทอื่นที่หัวข้อคล้ายกัน

ถ้าคำอธิบายกำกวมเกินไปจนหา subject ที่เจาะจงไม่ได้เลย (เช่น "/rename แก้บั๊ก" เฉยๆ) ให้ถามกลับสั้นๆ หนึ่งคำถามเพื่อขอ subject แทนการเดาแบบกว้างๆ ที่จะ search ไม่เจอ

### 3. เลือก Category prefix
ใช้ตัวใดตัวหนึ่งต่อไปนี้ถ้าตรงกับงาน — ถ้าไม่มีตัวไหนตรงเลยค่อยตั้งคำใหม่เอง (หนึ่งคำ, Title Case):

| Prefix | ใช้เมื่อ |
|---|---|
| `[Debug]` | ตามหา/แก้ปัญหา error, bug, พฤติกรรมผิดปกติ |
| `[Build]` | สร้าง feature หรือระบบใหม่ |
| `[Design]` | ออกแบบ architecture, schema, UI/UX |
| `[Report]` | สรุปผล, รายงานสถานะ |
| `[Research]` | ค้นคว้า, เปรียบเทียบตัวเลือก |
| `[Review]` | ตรวจโค้ด, ตรวจ PR, ตรวจเอกสาร |
| `[Plan]` | วางแผน, roadmap, กลยุทธ์ |
| `[Fix]` | แก้ไขจุดที่รู้สาเหตุแล้วแน่ชัด (ต่างจาก Debug ที่ยังไม่รู้สาเหตุ) |
| `[Setup]` | ติดตั้ง, config เครื่องมือ/environment |
| `[Learn]` | ศึกษาแนวคิดหรือเทคโนโลยีใหม่ |
| `[Migrate]` | ย้ายระบบ, อัปเกรดเวอร์ชัน |

### 4. ประกอบชื่อ
รูปแบบ: `[Category] <ชื่อที่เจาะจง ≤8 คำ>`

### 5. Self-check ก่อนตอบ
ไล่เช็คกับ Core Rules ทั้ง 6 ข้อก่อนส่ง: มี prefix ไหม, ไม่เกิน 8 คำ (ไม่นับ prefix) ไหม, เป็นอังกฤษล้วนไหม, มีชื่อเฉพาะที่ search เจอไหม (ไม่ใช่แค่คำกริยากว้างๆ), ไม่ใช่การแปลประโยคผู้ใช้ตรงๆ ใช่ไหม ถ้าไม่ผ่านข้อไหนให้แก้ก่อนตอบ

### 6. ตอบกลับ
ส่งชื่อในรูปแบบ inline code บรรทัดเดียวเพื่อให้ copy ง่าย ตามด้วยบรรทัดสั้นๆ เตือนว่าต้อง copy ไปเปลี่ยนชื่อเองบน claude.ai (skill นี้ไม่ได้เปลี่ยนชื่อให้อัตโนมัติ):

```
`[Debug] Node.js Express Memory Leak in Docker`

Copy ชื่อด้านบนไปแปะเปลี่ยนชื่อ Chat/Task บน claude.ai ได้เลย
```

## Edge cases
- **คำอธิบายครอบคลุมหลายงานในตัวเดียว** (เช่น ทั้ง debug และเขียน report) → เลือก category ของงานหลักที่เป็นจุดประสงค์จริงของบทสนทนานี้ ไม่พยายามยัดทุกอย่างลงในชื่อเดียว
- **คำอธิบายสั้นมากแต่มี subject ชัดเจน** (เช่น "/rename รีวิว PR #482 ของ auth service") → ตั้งชื่อได้เลยโดยไม่ต้องถามเพิ่ม เพราะมี category และ subject ครบแล้ว
- **ผู้ใช้ระบุชื่อที่อยากได้มาด้วยอยู่แล้วบางส่วน** → เคารพคำที่ผู้ใช้ระบุ ปรับให้เข้ากับ format (prefix + ความยาว) แทนที่จะคิดชื่อใหม่ทั้งหมด
